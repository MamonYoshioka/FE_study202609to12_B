# 基本情報技術者試験 学習記録

- 受験目標日：2026年12月24日
- 勤務日の学習時間：30分程度
- 休日の学習時間：2時間程度

## 学習スタンス

### 理解してから問題を解く

全く分かっていない状態で過去問を大量に解くことはしません。

最初にキタミ式で基本的な仕組みを理解し、例題や少数の基本問題で理解度を確認します。

基本的な学習の流れは、次のとおりです。

1. キタミ式で小さな範囲を学ぶ
2. 本を見ながら例題を解く
3. 本を閉じて基本問題を解く
4. 間違えた理由を確認する
5. 翌日以降にもう一度解く

### テキストを読むだけで終わらせない

キタミ式を最初から最後まで読むこと自体を目標にはしません。

学習した内容について、次のいずれかができる状態を目指します。

- 自分の言葉で説明できる
- 基本問題を解ける
- 間違った選択肢の理由を説明できる
- プログラミングや実務と結びつけられる

### 問題数より理解を優先する

学習初期は、問題を何十問も解くことより、少数の問題について解き方を説明できることを優先します。

理解が進んだ分野から、徐々に問題演習の量を増やします。

問題演習中心に切り替える目安は、次のとおりです。

## 科目Bの進め方

科目Bは、科目Aの学習が終わるまで待たず、最初から並行して学習します。

学習初期は週1〜2回程度から始め、少しずつトレースに慣れていきます。

主な学習順序は、次のとおりです。

1. 変数と代入
2. 条件分岐
3. 繰り返し
4. 一次元配列
5. 二次元配列
6. 探索とソート
7. 関数
8. 再帰
9. リスト・スタック・キュー
10. 木構造

問題を頭の中だけで処理せず、変数や配列の変化を表に書いて確認します。

## プログラミングとの結びつけ方

アルゴリズムは、試験問題だけでなくTypeScriptでも実装します。

特に次の内容は、コードを書いて動きを確認します。

- 線形探索
- 二分探索
- バブルソート
- 選択ソート
- スタック
- キュー
- 再帰処理

ただし、コードを丸暗記することは目標にしません。

次の内容を説明できる状態を目指します。

- どのような順番で処理しているか
- 変数や配列がどのように変化するか
- なぜその処理で答えが求められるのか
- どの程度の計算量になるか

## 間違えた問題の扱い

間違えた問題では、正解だけでなく原因を確認します。

主な原因を、次のように分類します。

- 知識が不足していた
- 計算手順を間違えた
- 問題文を読み違えた
- 擬似言語を正しく追えなかった
- 選択肢の意味を理解できなかった
- 単純な見落としをした

間違えた問題は、解説を読んで終わりにせず、翌日以降にもう一度解きます。

## 継続するためのルール

- 毎日完璧に学習することを求めない
- 予定どおりできなかった内容を翌日にすべて上乗せしない
- 時間がない日は、復習や問題1問だけでもよい
- 体調が悪い日は無理をせず、学習時間を短くする
- 教材を増やしすぎず、決めた教材を繰り返し使う
- 他人の学習量ではなく、自分の理解度を基準にする
- 学習記録を残し、できるようになったことも確認する

## 最終的に目指す状態

試験合格だけでなく、次の状態を目指します。

- ITの基本用語を自分の言葉で説明できる
- 2進数や計算量などの基礎を理解している
- アルゴリズムの処理を順番に追える
- 基本的な探索やソートをコードで表現できる
- ネットワークやデータベースの知識をWeb開発と結びつけられる
- 分からない問題に対して、どこが分からないかを判断できる

基本情報技術者試験の勉強を、資格取得だけで終わらせず、今後のWeb開発とコンピュータサイエンス学習の土台にします。
